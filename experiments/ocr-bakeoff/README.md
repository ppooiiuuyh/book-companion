# OCR 엔진 비교 테스트 (파일럿 5쪽)

## 결론

- **초벌 엔진은 Tesseract 5 `-l kor --psm 4`로 정합니다.** 본문 쪽 글자 오류율(CER)은 약 1%, 핵심 개념어 정확도는 97%(94/97)입니다. 속도는 기본 설정에서 쪽당 약 4.8초였지만, 스레드를 1개로 고정하고 쪽 단위로 병렬 처리하면 약 0.7초까지 줄어듭니다(아래 추가 실험 참고).
- **한국어 모델은 `tessdata_fast`(1.7MB, apt 기본값)를 씁니다.** 처음에는 표준 `tessdata`가 글자 정확도로 근소하게 앞서 채택했지만, **표준 모델은 한글 음절마다 공백을 넣어 띄어쓰기가 완전히 깨지는 문제**가 있어 철회했습니다(아래 "정정" 참고).
- **언어 설정에서 `eng`를 빼는 것이 가장 큰 개선이었습니다.** `kor+eng`에서는 굵은 글씨나 강조된 한글을 영문 글자로 잘못 읽었습니다(무엇이든 → `SHOE`, 성장을 → `TBS`). 설계서 v0.1의 오인식 표에 실린 오류들은 대부분 이 설정 때문이었습니다.
- **MinerU는 이 환경에서 실행할 수 없었습니다.** 모델 저장소(modelscope.cn, huggingface.co)와 mineru.net이 조직 네트워크 정책으로 막혀 있습니다. 클라우드 작업 공간과 Mac의 VM 모두 같습니다.
- **RapidOCR(PaddleOCR)도 한국어 모델을 받지 못했습니다.** 모델이 modelscope.cn에만 있어서, 기본 중국어 모델로 실행된 결과는 비교에서 제외했습니다.
- 대신 GitHub에서 모델을 받을 수 있는 **EasyOCR**로 대체 비교했습니다. Tesseract kor보다 정확도가 낮고(CER 약 6%) 5배 느렸습니다.

| 지표 | **CER** = 편집거리 ÷ 정답 글자 수 · **재현율** = 맞힌 글자 ÷ 정답 글자 · **정밀도** = 맞힌 글자 ÷ 출력 글자 · **개념어** = 핵심어 26종의 등장 횟수 일치 |
| 환경 | 클라우드 작업 공간, CPU 2코어, RAM 7GB, GPU 없음 |

## 쪽별 CER

| 쪽 | 유형 | kor+eng psm3 | **kor psm4** | kor psm6 | EasyOCR |
|---|---|---|---|---|---|
| p005 | 목록, 강조, 소제목 | 14.0% | **1.1%** | 0.5% | 5.6% |
| p009 | 소제목, 괄호 작은 글씨 | 22.3% | **0.0%** | 0.0% | 7.3% |
| p016 | 그래프, 주·출처, 영문 | 44.9% | **35.4%** ¹ | 33.7% ¹ | 34.8% ¹ |
| p023 | 숫자·수식·따옴표 | 8.1% | **1.1%** | 0.1% | 6.1% |
| p041 | 사진, 캡션 | 32.9% | **1.2%** | 67.4% ² | 7.2% |

¹ 대부분이 그래프 눈금·수치의 삽입입니다. 그래프 수치 6개와 라벨 10개는 kor psm4와 psm6에서 모두 찾았습니다(6/6, 10/10).
² psm6은 쪽 전체를 한 덩어리로 보기 때문에 사진 속 무늬를 글자로 대량 출력했습니다. psm4는 이 잡음이 거의 없었습니다.

**psm4를 고른 이유:** 본문만 보면 psm6이 약간 더 정확하지만, 사진이 있는 쪽에서 잡음이 폭발하고 속도도 1.5배 느립니다. psm4(1단 가변 크기 텍스트)가 이 책의 조판에 가장 잘 맞습니다.

## kor psm4에 남은 오류 유형 (교정 단계가 처리할 것)

| 유형 | 예 | 대응 |
|---|---|---|
| 영문 단어 소실 | `TV` → `1\`, `Luxemburg Income Study` → 숫자 잡음 | 영문이 섞인 줄만 `eng`로 다시 읽거나 Claude가 교정. 이 책은 영문이 드물어 부담이 작음 |
| `%` 인식 실패 | `50%` → `509`, `20%` → `208` | lint 규칙: "숫자 뒤 9/8 + 조사" 패턴을 교정 후보로 표시 |
| 유사 글자 | 갸루 → **가루**, 사회 → **사희**, 벌 → 별, 나눠 → 나뉘 | 용어집 lint (갸루, 사회 등) + Claude 교정 |
| 문단 첫 글자 누락 | `계층 문제를` → `층 문제를` | Claude 교정 (들여쓰기 위치) |
| 따옴표 종류 혼동 | ‘ ’ → " | 정규화로 흡수 (의미 영향 없음) |

## 설계에 반영할 것

1. **`ocr_draft.py`**: `tesseract -l kor --psm 4`, TSV로 줄·bbox·신뢰도 저장
2. **영문 보조 패스(선택)**: 신뢰도가 낮고 Latin 비율이 높은 줄만 `-l eng`로 다시 읽기
3. **lint 규칙 추가**: `%` 패턴, 용어집 유사형(가루/갸루, 사희/사회, 증류/중류)
4. **교정 비용 하향 조정**: 본문 CER이 약 1%라서 쪽당 패치가 수 줄 수준으로 줄어듭니다. 설계서 v0.1의 파싱 출력 추정(약 12만 토큰)은 더 줄어들 가능성이 큽니다.
5. **전체 처리 시간**: 224쪽 × 4.8초 ≈ 18분(1코어). 2코어로 나누면 약 10분
6. **MinerU**: 레이아웃 판별이 꼭 필요해지면 두 가지 방법이 있습니다. 조직 네트워크 허용 목록에 modelscope.cn이나 huggingface.co를 추가하거나, Mac에서 모델(약 0.8GB)을 직접 받아 연결 폴더에 두는 것입니다. 지금 결과로는 필요성이 낮습니다.

## 추가 실험: 한국어 모델 3종 비교 (2026-09-28)

Tesseract 5.3.4의 한국어 모델 세 가지를 같은 5쪽으로 비교했습니다. 모델은 모두 `raw.githubusercontent.com`에서 받았습니다. 시간은 `OMP_THREAD_LIMIT=1`로 1스레드를 고정하고 2회 측정한 평균입니다.

| 모델 | 파일 크기 | psm4 CER | 본문 4쪽 오류 글자 수¹ | 개념어 | psm4 속도(초/쪽) | psm6 속도 |
|---|---|---|---|---|---|---|
| `tessdata_fast` (apt 기본값) | 1.7 MB | 5.8% | 28 | 94/97 | **1.24** | 1.66 |
| **`tessdata` (표준, LSTM + legacy)** | 15.3 MB | **5.3%** | **21** | **95/97** | 1.52 | 1.92 |
| `tessdata_best` | 12.5 MB | 5.8% | 26 | 91/97 | 2.48 | 3.56 |

¹ p005, p009, p023, p041의 편집거리 합계로, 전체 약 8,400자 중 틀린 글자 수입니다. p016은 그래프 눈금이 섞여 있어서 뺐습니다.

- **`best`는 이 책에서 이득이 없었습니다.** 2배 느리고, 따옴표로 감싼 개념어(‘중상’, ‘중하’)를 오히려 더 놓쳤습니다.
- **`tessdata` 표준 모델이 근소하게 가장 좋았습니다.** 오류 글자가 28개에서 21개로 줄었고 시간은 약 23% 늘었습니다. 다만 5쪽 표본이라 차이가 작아서, 오차 범위 안일 수 있습니다.
- **psm6은 세 모델 모두 사진 쪽(p041)에서 잡음이 폭발했습니다.** psm4를 유지합니다.

### 처리 시간에 대한 새 발견: 스레드 설정

| 실행 방식 | 쪽당 시간 |
|---|---|
| 기본값 (OpenMP 멀티스레드, 2코어) | 약 4.8초 (본 실험 초반 측정) |
| `OMP_THREAD_LIMIT=1`, 1쪽씩 | 약 1.2초 |
| `OMP_THREAD_LIMIT=1`, 2코어 병렬(쪽 단위) | **약 0.7초** (5쪽에 3.6초) |

코어가 2개뿐인 환경에서는 Tesseract 내부 멀티스레딩이 오히려 크게 느려졌습니다. **스레드를 1개로 고정하고 쪽 단위로 병렬 처리**하면 224쪽 전체를 **약 3분**(표준 모델이면 약 3~4분)에 끝낼 수 있습니다.

### 결정 (정정 반영)

- 초벌 엔진: **Tesseract 5 + `tessdata_fast` `kor` 모델, `--psm 4`, `OMP_THREAD_LIMIT=1`, 쪽 단위 병렬**
- 모델 파일은 프로젝트의 `models/tessdata/`에 두고 `--tessdata-dir`로 지정합니다.

## 정정 (2026-09-28, 구현 중 발견)

### 1. 표준 `tessdata` 모델의 띄어쓰기 붕괴

앞의 비교는 공백을 지우고 글자만 비교했기 때문에, 띄어쓰기 문제를 놓쳤습니다. 줄 안의 띄어쓰기를 따로 채점한 결과는 다음과 같습니다(`scripts/space_score.py`, 줄바꿈 경계는 제외).

| 모델 (psm4) | 띄어쓰기 정밀도 | 재현율 | F1 |
|---|---|---|---|
| `tessdata_fast` | 0.997 | 1.000 | **0.998** |
| `tessdata` 표준 | 0.333 | 1.000 | **0.499** (음절마다 공백: "당 신 은 하 류 인 가 ?") |
| `tessdata_best` | 1.000 | 0.997 | 0.998 |

앞서 "Mac VM의 구버전 Tesseract(4.1.1)가 음절마다 공백을 넣는다"고 판단했지만, 원인은 버전이 아니라 **그때 쓴 표준 모델**이었습니다.

### 2. 글자 수 측정 오류

이 환경은 로케일이 설정되어 있지 않아 `wc -m`이 **바이트 수**를 셌습니다(한글 1자 = 3바이트). 그래서 앞의 글자 수 표기가 실제보다 약 2.3배 컸습니다.
- 정답 5쪽: "약 9,800자"라고 했지만 **실제 4,309자**(공백 포함)
- "본문 4쪽 약 8,400자 중 오류 N개"라고 했지만 **실제 약 3,300자 중**
- 오류율(CER)은 파이썬으로 계산했기 때문에 **영향 없음**
- 책 전체 분량도 "약 40만 자"가 아니라 **약 20만 자**(OCR 기준 197,648자)입니다.

## 재현 방법

```bash
# 1) 원본 이미지 추출
python scripts/extract_pages.py "하류사회(2025-09).pdf" 5,9,16,23,41 pages
# 2) Tesseract 실행 (tesseract-ocr-kor 필요)
scripts/run_tesseract.sh kor 4 outputs/tesseract_kor_psm4
# 3) EasyOCR (모델은 GitHub releases의 craft_mlt_25k, korean_g2)
python scripts/run_easy.py
# 4) 채점
python scripts/score.py tesseract_kor_psm4 easyocr_ko+en
```

- `score_summary.txt`: 쪽별 CER과 놓친 개념어 목록
- `scores.json`: 전체 수치
- `outputs/`: 엔진별 원시 출력
