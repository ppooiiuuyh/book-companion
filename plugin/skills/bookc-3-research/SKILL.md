# 3단계: 조사 (4개 영역 병렬 → 병합)

인자: PDF 경로·파일명·책 폴더 이름. 선행 단계: 1(인테이크) — 서지 정보와 장 목록이 필요하다. 2단계와 동시에 진행해도 된다.

`PLUGIN/references/runtime.md`의 준비 → 책 찾기 → 내려받기 → `$BC can $B research` (불가하면 안내문 전하고 끝).

## 절차

1. **남은 일**: `$BC ready $B`에서 `kind`가 `research`인 줄(남은 영역)과 `research-merge`를 본다. `status.research.done`이면 결과 요약만 보여 주고 끝낸다.
2. **영역 조사 — 병렬**: 남은 영역마다 서브에이전트(general-purpose) 하나씩, **한 메시지에 여러 Agent 호출**로 동시에 띄운다(최대 4). 각자에게 아래 "영역 작업자 지시문"을 준다.
3. **병합** (영역 파일 4개가 모두 생기면, 직접 한다):
   - `research/_parts/*.md`를 모두 읽고 출처를 합친다. 같은 URL이나 같은 글의 재게시는 하나로 합치고, 번호를 새로 매긴다(`[1]`…).
   - `B/research/`에 네 파일을 쓴다. 모든 주장에 새 번호의 출처를 단다. 각 파일 머리에 frontmatter(`book`, `layer: research`, `generated`)를 둔다.
     - `sources.md` — 번호, 제목, 사이트, 날짜, 유형(서점/블로그/기사/학술/원서), URL, 한 줄 요지
     - `highlights.md` — 독자들이 꼽은 핵심 주장, 인상 깊은 부분, 자주 인용되는 대목. `$BC outline $B`의 장 목록에 맞춰 장을 표시한다. 여러 영역에서 겹친 것은 "여러 출처 공통"으로 표시한다
     - `critiques.md` — 비판·반론·한계(방법론, 표본, 시대성, 번역 품질 등). 찬반이 갈리는 지점은 양쪽 출처를 함께 단다
     - `watchlist.md` — 통독 때 확인할 질문. 형식: `- [ ] Q3. (제4장) 연봉 300만 엔 기준의 근거 데이터는? — 출처 [5][8]`. 4단계에서 답을 채운다
   - `_parts/`는 지우지 않는다. 기록으로 남긴다.
4. `$BC mark $B research --files sources.md,highlights.md,critiques.md,watchlist.md` 다음 체크포인트.
5. **보고**: 출처 수(유형별), 하이라이트 3개, 주요 논쟁점 2–3개, watchlist 질문 수를 짧게 보고한다.

## 영역 작업자 지시문

> 『{title}』({author} 지음, {translator} 옮김, 원제 {original}) 조사 중 **{part}: {scope}** 영역만 맡습니다. 장 목록은 다음과 같습니다: {outline 장 표}.
> WebSearch로 여러 검색어 조합(제목·저자·원제·핵심어)을 써서 찾고, WebFetch로 읽습니다. 가져올 수 없는 페이지는 건너뜁니다. curl 같은 다른 수단으로 우회하지 않습니다. 원문을 길게 옮기지 말고 요지를 자기 말로 정리하며, 인용은 짧게만 합니다.
> 결과는 `{book}/research/_parts/{part}.md` 한 파일로 씁니다. 구성은 `## 출처`(번호·제목·사이트·날짜·URL·한 줄 요지), `## 주요 내용·하이라이트`(장 표시), `## 비판·논쟁`, `## 통독 때 확인할 질문`이며, 모든 항목에 이 파일 안의 출처 번호를 답니다. 찾은 게 적으면 적은 대로 쓰고, "이 영역은 자료가 적음"이라고 밝힙니다.
> 끝나면 출처 수와 가장 중요한 발견 2개만 한 줄로 돌려줍니다.

## 규칙

- 외부 의견은 `research/`에만 둔다. source.md와 study.md에 섞지 않는다.
- 출처 없는 주장은 쓰지 않는다. 블로그 한 곳의 주장은 "한 리뷰어는"처럼 범위를 밝힌다.
- 기본은 스포일러 걱정이 없는 논픽션이다. 소설이면 결말 관련 내용은 `watchlist.md`에 "결말 관련"으로만 표시한다.
