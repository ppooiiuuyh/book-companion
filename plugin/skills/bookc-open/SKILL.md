# 책 열기 (대화 모드)

인자: 책(PDF 파일명·책 폴더 이름·제목). 선행 조건: 적어도 한 장의 파싱이 끝나 있어야 한다. 5단계까지 안 됐으면 있는 층만으로 대화하고, 빠진 층을 처음에 한 줄 알린다(예: "통독 메모와 종합이 아직 없어 원문과 요약만으로 답합니다 — /bookc 로 이어서 만들 수 있습니다").

## 열기

1. 책을 찾는다(runtime.md 3절). 방식 A에서는 **내려받기 없이** 기기에서 직접 읽는다: 텍스트 파일은 `device_bash`로 `cat`/`grep`, 도표 이미지를 봐야 할 때만 그 파일을 스테이징해서 Read한다.
2. 처음에 읽을 것(이 순서, 있는 것만): `index.md` → `insights.md`(있으면) → `glossary.md` → `reading/_carry.md`. 합쳐 약 1만 토큰 이내. 원문 전체를 미리 읽지 않는다.
3. 사용자에게 한두 줄로: 책 제목, 준비된 층, 무엇을 물어볼 수 있는지.

## 답하기

- 질문이 가리키는 장·절을 index 목차와 `study.md`로 좁히고, 근거는 `source.md`의 해당 부분을 `grep -n`이나 앵커 범위로 읽어 확인한다.
- 답에 근거 앵커를 단다: `(제4장 p087-b3, 인쇄 95쪽)` — 인쇄 쪽 = PDF 쪽 + `printed_page_offset`.
- 층을 구분해 말한다: 저자의 주장(원문) / 요약 / Claude의 해석(reading·insights) / 외부 평가(research, 출처 포함).
- 사용자가 책의 주장에 동의하거나 반대하면 insights.md의 관련 반박 지점(R 번호)과 저자 측 재반박을 함께 꺼내 토론을 돕는다.
- 원문을 길게 옮기지 않는다. 필요한 문장만 짧게 인용하고 나머지는 풀어 말한다.
- 사용자가 새로운 해석이나 질문을 내놓으면, 원하면 `reading/conversation-notes.md`에 날짜와 함께 덧붙인다(사용자 요청 시에만, 기기 파일에 직접 append).
- 원문 오류를 발견하면 알려 주고, 사용자가 원하면 해당 쪽 review를 고쳐 그 장만 다시 조립한다(2단계 6번 절차).
