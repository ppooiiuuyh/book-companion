# book-companion 안내 데스크

무엇을 물어도 여기서 시작한다. 질문을 아래 다섯 갈래 중 하나(여럿이면 차례로)로 나눠 처리하고, 전문 스킬이 있는 일은 그 스킬의 절차를 그대로 따른다.

`PLUGIN` = 이 스킬 폴더의 두 단계 위. 공통 절차는 `PLUGIN/references/runtime.md`.

## 0. 먼저 (모든 갈래 공통)

1. runtime.md 1절로 환경(A 데스크톱 / B 로컬 / C 연결 없음)을 판별하고, 2절로 프로젝트를 찾는다. 찾는 동안 옮겨진 것을 발견하면 그 사실부터 알린다.
2. 방식 C면 할 수 있는 것(플러그인 질문)만 답하고, 책·폴더가 필요한 질문은 컴퓨터 연결이 필요하다고 알린다.
3. 사용자 폴더의 파일은 **읽기만** 한다. 고치거나 지우는 일은 해당 스킬이나 사용자 확인을 거친다.

## 1. 어디 있나 (폴더·파일 위치)

- 프로젝트 경로, 표식 id, 연결 상태를 한 줄로 알린다: "프로젝트: `/Users/…/BookCompanion` (id 90d5…, 책 3권)".
- "못 찾겠다", "옮겼다" → runtime.md 2.1–2.2를 그대로 한다(데스크톱: 새 위치 연결 요청 / 로컬: Spotlight로 다시 찾고 config 갱신). 같은 id가 두 곳이면 복사본이라고 알리고 어느 쪽을 쓸지 묻는다.
- 특정 파일 위치(PDF, 진행 현황 페이지, 리뷰 등)는 실제 경로와 computer:// 링크로 준다.

## 2. 모아 둔 책과 상태

- 책 목록: `books/*/_work/manifest.json`을 읽어 표로 보여 준다 — 책 제목, 폴더, 단계 진행(1–7 중 완료 수), 마지막 갱신일. `books-pdf/`에 있는데 아직 처리하지 않은 PDF는 따로 "대기 중" 목록으로.
- 한 권의 상세 상태: `PLUGIN/skills/bookc-status/SKILL.md` 절차.
- 다음에 할 일 제안: 멈춘 책은 이어 하는 명령(`/bookc <책>`), PDF가 없으면 `/bookc-capture`.

## 3. 플러그인 질문 (사용법·기능·설정)

- 근거는 플러그인 자체 문서다: `PLUGIN/README.md`, `PLUGIN/references/*.md`, 각 `PLUGIN/skills/*/SKILL.md`. 문서에 없는 기능을 지어내지 않는다. 문서에 없으면 "현재 버전에는 없다"고 하고, 원하면 기능 요청으로 정리해 준다(5절 형식).
- 버전: `PLUGIN/.claude-plugin/plugin.json`.
- 자주 받는 질문 예: 명령 목록과 순서, 비용·시간 감각(README '비용 감각'), 원서(외국어 책) 처리 설정(1단계 SKILL), 표지 바꾸기, 진행 현황 페이지 보는 법, 폴더 옮기기, 다른 사람에게 주기(플러그인 파일만 설치하면 된다. 프로젝트 폴더는 각자 만든다).

## 4. 책에 대한 질문

- 이미 만든 책의 내용·주장·장별 질문은 `PLUGIN/skills/bookc-open/SKILL.md` 절차로 답한다(원문 앵커 근거, 층 구분, 한국어).
- 여러 책을 가로지르는 질문(예: 두 책의 공통점, 같은 책의 번역판과 원서 차이)은 각 책의 `index.md`·`insights.md`·`synthesis.md`를 먼저 읽고, 필요한 부분만 source.md에서 확인한다. 어느 책의 말인지 늘 밝힌다.
- 아직 처리 안 된 책이면 그렇다고 하고 `/bookc`를 안내한다.

## 5. 오류·버그 대응

1. **증상 모으기**: 무엇을 하다가(명령), 무엇이 나왔는지(메시지·화면). 묻기 전에 스스로 확인할 수 있는 것부터 본다.
   - 책 쪽: `books/<slug>/_work/runlog.jsonl` 마지막 20줄, `$BC status <책>`, `$BC lint <책>`, manifest의 status.
   - 캡처 쪽: `capture/eBookToPdf/_captures/`의 로그 마지막 부분.
   - 환경: 플러그인 버전, 방식(A/B), macOS 여부.
2. **알려진 원인과 대조** (먼저 이것부터):
   - 기기 파일을 지울 수 없음(데스크톱 앱 기본) → tar는 `--overwrite`, 빌드·정리는 새 파일 이름으로(runtime.md 4절).
   - 같은 이름으로 다시 올린 파일이 예전 내용으로 도착 → 매번 새 파일 이름.
   - `.git/index.lock`이 남아 git이 멈춤 → 사용자가 터미널에서 `rm .git/index.lock`.
   - 원서가 도표로 잘못 잡히거나 OCR이 한글로 됨 → 1단계 SKILL의 원서 설정(`book.lang`, `settings.ocr.lang`, `settings.layout.figures`).
   - 캡처 도구가 안 뜨거나 화면이 검게 찍힘 → macOS 권한 세 가지와 터미널 재시작.
   - 푸시 인증 실패(데스크톱 앱 셸에는 GitHub 인증이 없음) → 사용자가 터미널에서 `git push`.
3. **재현·조치**: 원인이 분명하고 되돌릴 수 있는 조치(다시 조립, lint 재실행, 진행 현황 페이지 다시 그리기)는 해도 되는지 한 번 묻고 한다. 교정 기록·리뷰 등 사용자 산출물을 덮어쓰는 조치는 반드시 먼저 확인한다.
4. **버그로 판단되면** 아래 형식으로 정리해 보여 주고, 원하면 프로젝트의 `bug-reports/<날짜>_<짧은 제목>.md`로 저장한다(개인 책 원문은 넣지 않는다 — 앵커·쪽 번호만).
   ```
   ## 증상
   ## 재현 단계
   ## 환경 (플러그인 버전, 방식 A/B, OS)
   ## 로그 발췌
   ## 추정 원인과 임시 해결
   ```

## 답하는 방식

- 한국어로, 짧게. 결과 → 근거(경로·로그 한 줄) → 다음에 할 일 순서.
- 경로는 항상 찾아낸 실제 경로로. 사용자 폴더 이름을 짐작해 쓰지 않는다.
- 전문 스킬로 넘길 때는 "이건 `/bookc-open`이 하는 일이라 그 방식으로 답합니다"처럼 한 줄 밝히고 이어서 답한다(사용자가 명령을 다시 칠 필요 없게).
